HTML: The skeleton of the web

HTML stands for HyperText Markup Language. It isn't here to look pretty; it simply tells the browser: this is a heading, that is a paragraph, this is an image and that is a button.

Basics

A tag is a pair of "bracket instructions"

Most HTML elements are made of an opening tag and a closing tag, with the content sitting between them. The closing tag adds a slash.

Tag structure 
<p>Some text</p>
<!--  opening tag   content   closing tag -->

<h1>A heading</h1>
<a href="https://example.com">A link</a>

Elements with no content, such as <img> and <meta>, are called "empty elements" and need no closing tag.

Attributes are extra notes for a tag For example, href tells a link where to go and src tells an image where to load, written as name="value" inside the opening tag.
Document Structure

Every page has a fixed set of four pieces

Page skeleton 
<!DOCTYPE html>            <!-- Declaration: this is HTML5 -->
<html lang="en">      <!-- Root of the page, language set to English -->
<head>
  <meta charset="UTF-8">  <!-- Character encoding, avoids garbled text -->
  <title>Name shown on the browser tab</title>
</head>
<body>                <!-- Everything users can see goes here -->
</body>
</html>

<head>

Invisible to users; it holds information for the browser and search engines: encoding, title, icons, stylesheets and the share card.

<body>

All the visible, clickable content on the page is written inside the body.

Nesting

Tags can be layered, but they must open and close in pairs, like brackets that never cross.

Semantic HTML

Using the right tag beats wrapping everything in divs

Semantics means "know the purpose from the tag": use nav for navigation and article for an article. Machines understand it, and so do screen readers.

<header> site header + <nav> navigation
<main> main content
<article> a standalone article
<aside> sidebar
<footer> footer information
  • header / footer: the head and tail of a page or block
  • nav: a collection of navigation links
  • main: the unique main content of the page
  • article: self-contained content, such as a post
  • section / aside: a content block / a side note
Why does it matter? With the same visual result, semantic tags make the page easier for search engines to understand and let people using screen readers browse smoothly — this is web accessibility.

Forms

The standard way to collect user input

The form itself only handles how things look; processing the data usually needs a back end. This project has no server, so only the structure is shown.

form example

  <label>Nickname
    <input type="text"
           placeholder="Type here">
  </label>
  <input type="checkbox"> Remember me
  <button type="submit">
    Submit
  </button>
</form>
